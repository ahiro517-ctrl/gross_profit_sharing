# 粗利見える化ツール

Google スプレッドシート + Google Apps Script(GAS)で構築する社内ツール。
社員が自ら粗利目標を意識し、案件を通じた達成状況を見える化する(仕様書 v1.1 準拠)。

- 対象規模:約20名(最大30名)・2ユニット体制
- スタック:Google Sheets + GAS(clasp 管理)・外部サービスなし
- 金額:税抜・円・整数

## セットアップ手順

> 📘 **はじめてセットアップする方へ**:Node.js のインストールから動作確認まで
> 画面操作レベルで説明した **[非エンジニア向けセットアップマニュアル](docs/SETUP.md)** を用意しています。
> 以下はエンジニア向けの要約です。
>
> 📗 **セットアップが終わった方へ**:入力操作とビューの見方は
> **[利用ガイド](docs/USER_GUIDE.md)** を参照してください(15分のお試しツアー付き)。

### 1. clasp でデプロイ

```bash
npm install -g @google/clasp
clasp login

# 新規スプレッドシートごと作る場合
clasp create --type sheets --title "粗利見える化ツール" --rootDir src
# 既存スプレッドシートに紐づける場合:
#   スプレッドシートの 拡張機能 > Apps Script からスクリプトIDを取得し、
#   .clasp.json.example をコピーして .clasp.json を作り scriptId を記入

clasp push
```

> `.clasp.json` は環境ごとに異なるため git 管理しません(`.gitignore` 済み)。

### 2. スプレッドシート側の初期化

1. スプレッドシートを開き直す(メニュー「粗利ツール」が出る)
2. **粗利ツール > 管理者 > 初期セットアップ** を実行
   - 全シート(マスタ/貼付/案件データ/案件入力/分配入力/集計/ビュー/監査ログ)を生成
   - 等級・目標・ポジション単価・kintoneマッピング表などのマスタ初期値を投入
   - シート保護とビュー雛形を設定
   - 実行者が管理者として `設定_マスタ` に登録される
3. `設定_メンバー` にメンバーを投入(氏名/メール/ユニット/現等級/年次/評価対象/評価開始日/ユニット長)
4. **粗利ツール > 管理者 > 初期セットアップ** をもう一度実行(ビューのプルダウンにメンバー・ユニットを反映)
5. スプレッドシートの共有設定でメンバーに編集権限を付与

## 日常運用

| タイミング | 誰が | 操作 |
|---|---|---|
| 週次など | 誰でも | kintone CSV を `kintone貼付` に貼り付け → **粗利ツール > kintone取込** |
| キックオフ時 | メイン担当 | **案件登録(見積入力)**:見積の売上/原価/粗利を入力 |
| メンバー招集時 | メイン担当 | **制作分配を入力**(残り%は自動でメイン担当へ)/多数の子案件には**まとめ分配** |
| 現場に入ったら | 本人 | **現場分配を入力**(ポジション・日数0.5刻み。等級・単価は入力時点で固定) |
| 案件終了時 | メイン担当 | **確定値入力**(一度入れたら再編集不可。修正は管理者のみ) |
| 入力ミス時 | 入力者 | **分配取消**(論理削除)→ 再入力 |
| 半期末 | 管理者 | **管理者 > 半期締め**(当該半期をフォームから変更不可に) |

### kintone CSV 取込の仕組み(列ズレ対策)

- 貼り付けた1行目の**ヘッダー名**で列を特定します。列順が毎回違っても問題ありません
- 取込対象のヘッダー名は `設定_マスタ` の「kintone取込マッピング」で変更できます(コード修正不要)
- 必須ヘッダー(案件ID/案件名/取引先名/納品予定日_終/フェーズ)が見つからない場合は、
  **どのヘッダーが無いかを表示して取込を中断**します
- `案件データ` へは案件IDをキーに upsert(既存更新・新規追加)。下流はすべて案件ID参照のため列ズレが波及しません
- 案件所有者が複数記載(改行区切り)の場合は1行目を採用して警告。マスタと照合できない場合も警告
- 請求月は `納品予定日_終` の月を自動導出。例外(年間一括請求等)は案件登録時の「請求月上書き」で対応

### CSV が文字化けする場合(Shift-JIS フォールバック)

kintone の CSV は Shift-JIS(cp932)です。

1. 通常は スプレッドシートの ファイル > インポート で自動判別されます
2. 文字化けした場合:Googleドライブに CSV をアップロード → 右クリック >
   アプリで開く > Googleスプレッドシート(自動で文字コード変換される)→ 全選択コピーして `kintone貼付` へ
3. それでもダメな場合:エディタで開いて UTF-8 で保存し直してからインポート

## 計算モデル(実装仕様)

```
案件粗利 = 売上 − 社外原価(社員の稼働は原価ではなく粗利の分配)
現場稼働分配 = 等級×ポジション別の固定単価 × 日数(稼働時点でスナップショット)
  金額 = 1日単価 × 整数日 + 半日単価 ×(0.5日があれば1回)※半日は係数でなくマスタ値
制作稼働原資 = 案件粗利 − 現場稼働分配合計(赤字でもマイナスのまま%按分)
制作稼働分配 = 制作原資 × %(メイン担当の% = 100 − 他メンバー合計、自動行として常時メンテ)
```

- すべての分配は**案件の請求月**に帰属(稼働月ではない)。半期判定も請求月ベース(7〜12月=前期)
  - 半期ラベルは期初年で表記:`2026前期` = 2026/07〜2026/12、`2026後期` = 2027/01〜2027/06
- 見積時粗利と確定粗利は別カラムの2時点スナップショット。**評価には確定値のみ使用**
- 現場分は固定単価のため予測額=確定額(入力時点で確定扱い)。制作分は案件の確定値入力で確定額が立つ
- 来期請求の案件は個人ビューの「来期以降の計上分」枠に表示(稼働したのに見えない、を防ぐ)

## 「壊れない」ための実装

- 入力はすべてサイドバーフォーム経由。監査ログ(非表示シート)に全操作の変更前→変更後を記録
- 削除は無効フラグの**論理削除**のみ(分配取消)。スナップショット値は変更不可(取消→再入力)
- 確定値はフォームから再編集不可。修正は**管理者 > 確定値修正**のみ(ログに残る)
- ハードブロック:他メンバー%合計>100 / マスタ不整合 / 締め済み半期 / 確定値の再入力
- 警告のみ(止めない):赤字 / 制作%≠100 / 等級条件違反 / 所有者複数・照合不可 / 請求月未確定

### シート保護について(重要な制約)

コンテナバインドの GAS は「メニューを実行した本人」の権限で動くため、
メンバーの操作が書き込むシートをハード保護にするとフォーム送信自体が失敗します。そのため:

- `設定_マスタ` / `設定_メンバー`:**管理者のみ編集可(ハード保護)**
- `案件データ` / `案件入力` / `分配入力` / `集計` / `監査ログ` / 各ビュー:**警告付き保護**
  (直接編集しようとすると警告ダイアログ。改ざんは監査ログ+再計算による上書きで検知・修復)
- `kintone貼付`:保護なし(全員貼付可)
- ビューのセレクタセル(B1)のみ警告なしで編集可
