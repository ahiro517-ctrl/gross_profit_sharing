# 粗利見える化ツール 仕様書 v2.0

Google スプレッドシート + Google Apps Script(GAS)で構築する社内ツール。
対象規模:約20名(最大30名)、2ユニット体制。2025後期(2026/01〜)から練習運用、2026前期(2026/07〜)から本格運用。

> **このドキュメントについて**
> v1.1 をベースに、第1次実装(2026/06)とその試用フィードバックで確定した仕様・追加機能・
> 実装上の注意をすべて反映した完全版。**新規リポジトリでこの1枚から再実装できる**ことを意図する。
> v1.1からの変更点は各所に【v2】マークで示す。

## 1. 目的

1. 社員が自ら粗利目標を意識し、案件を通じた達成状況を見える化する
2. ユニット長が部下の目標未達・稼働状況を見て案件アサインの相談に使う
3. 半期ごとに「誰がどれだけ粗利を出したか」を確定値で評価に使う

## 2. 基本となる計算モデル

```
案件粗利 = 売上 − 社外原価(外注費等)
※社員の稼働は原価ではなく「粗利の分配」として扱う

現場稼働分配 = Σ(等級×ポジション別の固定単価 × 日数)   ← 稼働時点の等級でスナップショット
  金額 = 1日単価 × 整数日 + 半日単価 ×(0.5日端数があれば1回)
  ※半日は係数計算ではなくマスタの半日単価を直接参照(端数ルールが揃わないため)
制作稼働原資 = 案件粗利 − 現場稼働分配合計
制作稼働分配 = 制作稼働原資 × メンバーごとの%(合計100%)
  メイン担当の% = 100 − 他メンバー%合計(システムが「自動行」として常時メンテナンス)

個人の粗利実績 = 自分への分配額の合計(現場分 + 制作分)
```

- 金額はすべて税抜・円・整数。表示は `#,##0`(カンマ区切り)書式【v2】

### 粗利の2時点スナップショット
- **見積時粗利(予測)**:キックオフ時にメイン担当が入力。以後上書きしない
- **確定粗利**:案件終了時に精算見積書/請求書ベースで入力。別カラムに保持
- 分配額も「予測分配額」「確定分配額」の両方を算出。**評価には確定値のみ使用**
- 現場分は固定単価のため予測額=確定額(**入力時点で確定扱い**)。制作分は案件の確定値入力後に確定額が立つ
- 【v2】**確定値入力後も分配(現場・制作)の追加入力は可能**(請求確定後に分配を整える運用を許容)。
  確定済み案件の分配の「取消」のみ管理者限定

### 期間帰属(最重要ルール)
- すべての分配は **案件の請求月** に帰属する。稼働月ではない
- 請求月は案件データから自動で引く。**分配の入力者に月を入力させない**
- kintone CSVに「請求月」列は存在しないため、**請求月 = `納品予定日_終` の月**を自動導出する
- 年間一括3月請求などの例外は、`案件入力` の「請求月上書き」欄でメイン担当のみ変更可能
  (登録後の変更は管理者メニュー「請求月上書き修正」)
- 複数月にまたがる案件も分割しない(請求月に全額計上)
- 今期に稼働しても請求が来期なら、今期のデータ上は空になる。これは仕様として許容
  (個人ビューの「次半期以降の計上分」枠で見える化する)
- 分配入力は半期の枠に縛らず、**先の案件もどんどん入力できる**こと

### 半期の定義と表記【v2】
- 前期:7月〜12月 / 後期:1月〜6月(期初は7月)。半期判定はすべて**請求月**ベース
- 半期ラベルは期初年で表記:`2026前期` = 2026/07〜2026/12、`2026後期` = 2027/01〜2027/06
- **画面・ビュー上の半期表示は必ず期間つき**にする:`2026前期(2026/07〜2026/12)`
  「今期」「来期」という相対表現だけの表示は禁止(試用で紛らわしいと判明)
- シートは半期ごとに作り直さず、**ずっと継ぎ足しで**使う。過去半期は「半期締め」で凍結する

### 赤字時のルール
- 現場稼働の固定単価は粗利が不足しても削らない(しわ寄せを出さない)
- 制作稼働原資がマイナスになった場合、**マイナスのまま%按分して制作メンバーに計上**する
- システムはハードブロックせず、**警告表示のみ**(案件行と関係ビューに赤字フラグ)

### 運用開始月(過去データの段階導入)【v2】
- 設定に「**運用開始月**」(例: `2026/01`)を持つ
- 請求月(未登録案件は自動導出値)が運用開始月より前の案件は:
  - 「やること」リスト・未入力一覧の対象外
  - 案件登録/現場分配/制作分配/まとめ分配の**選択肢から除外**
- kintoneの過去データは**削除しない**(取込は削除をしない仕様と整合)。見せない制御で対応する
- 空欄なら全期間が対象

|---|---------|------|---------|
| 1 | `設定_一般` | キー・バリュー設定/管理者/締め済み半期【v2分割】 | 管理者のみ |
| 2 | `設定_単価目標` | 等級・半期目標・ポジション単価【v2分割】 | 管理者のみ |
| 3 | `設定_取込` | kintoneヘッダー名マッピング表【v2分割】 | 管理者のみ |
| 4 | `設定_メンバー` | メンバー一覧 | 管理者のみ |

| 7 | `案件入力` | メイン担当が入力する案件単位の粗利情報 | GASフォーム経由 |
| 8 | `分配入力` | 現場/制作の分配明細(1行=1人×1案件×1種別) | GASフォーム経由 |
| 9 | `集計`(非表示) | 個人×月×予測/確定のピボット元データ | GASのみ |
| 10 | `V_個人` | 個人ビュー(プルダウンで人を選択) | 閲覧+セレクタのみ |
| 11 | `V_ユニット` | ユニット長ビュー(ユニット選択) | 閲覧+セレクタのみ |
| 12 | `V_経営` | 経営ビュー(全社+ユニット別) | 閲覧のみ |
| 13 | `監査ログ`(非表示) | 全フォーム操作の追記ログ | GASのみ |

> 【v2重要】v1では設定類を1シート内の横並びブロック(列位置固定)で持ったが、
> **ユーザーの行・列操作で構造が壊れる事故が起きやすい**ことが試用で判明。
> v2では設定を役割別の複数シートに分割し、**各シートは「1行目=ヘッダー、2行目以降=データ」の
> 単純な縦持ち表のみ**とする(横並びブロック禁止)。詳細は§10。

## 4. マスタ・設定定義

### 4.1 `設定_一般`(キー・バリュー縦持ち)

| キー | 初期値 | 用途 |
|------|--------|------|
| 期初月 | 7 | 半期の開始月 |
| ユニット長個人目標 | 5000000 | ユニット長の個人目標(円) |
| 運用開始月 | (空) | §2参照。例: 2026/01 |
| スキーマバージョン | (実装が管理) | §10参照 |

別列(または別表)で **管理者メール一覧** と **締め済み半期一覧** を縦持ちする。

### 4.2 `設定_単価目標`

**等級**:`b` → `a1` → `a2` → `l1`(半期評価で昇格)。順位列で上下関係を定義。
**等級名はメンバーマスタ・目標表・ポジション最低等級と参照整合が必要**(変更時は全箇所同時に)。

**半期粗利目標(等級×年次)**:

| 等級 | 年次条件 | 半期目標 |
|------|------|---------|
| b | 入社1年目 | 50万円 |
| b | 2年目 | 150万円 |
| b | 3年目 | 250万円 |
| a1 | — | 540万円 |
| a2 | — | 630万円 |
| l1 | — | 810万円 |

- 年次は**b等級の目標判定のみ**に使用【v2明文化】。a1以上は空欄でよい
- b等級で年次がマスタ上限を超える場合は最大年次の目標を適用
- ユニット長:個人目標は設定値(初期500万円)+ユニットメンバー合計目標の達成(ユニットビューに両方表示)

**ポジション×単価表(1日/半日を両方持つ)**:

| ポジション | 等級条件 | 1日 | 半日 |
|-----------|---------|------|------|
| ディレクター | a2以上 | 50,000 | 35,000 |
| アシスタントディレクター | a1以上 | 35,000 | 25,000 |
| スタッフ | 制限なし | 25,000 | 20,000 |

- ポジションは行追加で増やせる(マスタ駆動)
- 等級条件を満たさない組み合わせは**警告表示のみ、入力は可能**

### 4.3 `設定_メンバー`

| 列 | 用途 |
|----|------|
| 氏名 | 表示名(ビュー・フォームの選択肢) |
| メール | Googleアカウント。本人特定・kintone案件所有者との照合キー(小文字比較) |
| ユニット | 所属(表記は全員で統一) |
| 現等級 | b/a1/a2/l1(プルダウン) |
| 年次 | b等級のみ必須【v2明文化】 |
| 評価対象 | TRUE/FALSE(新卒3ヶ月・中途原則1年は対象外。自動判定はしない) |
| 評価開始日 | **計算には使わない運用メモ**【v2明文化】 |
| ユニット長 | TRUE/FALSE(個人目標が設定値に切り替わる) |

## 5. データフロー

### 5.1 kintone 取り込み(列ズレ対策が最優先)

過去にコピペ運用で列ズレ事故が発生済み。以下で防ぐ:

1. ユーザーは kintone から吐いた CSV を `kintone貼付` シートに丸ごと貼る(列順は毎回違ってよい)
2. メニュー「kintone取込」で GAS が:
   - **1行目のヘッダー名で列を特定**する(列位置に一切依存しない)
   - 必要な列だけ抽出し、`案件データ` へ **案件IDをキーに upsert**(既存は更新、新規は追加)
   - 【v2】書き戻し時に**請求月の新しい順に自動ソート**(請求月なしは末尾)
   - 必須ヘッダーが見つからない場合は**処理を中断し、どのヘッダーが無いかを明示**
   - 取込ログ(日時/新規n件/更新n件)をトーストと監査ログに残す
3. 【v2明文化】**取込は削除をしない**(追加・更新のみ)。部分的なCSV貼付でデータが消える事故を防ぐ。
   kintone側で消えた・見せたくない案件は「運用開始月」または失注フェーズで制御する
4. `案件データ` は手編集禁止(GASのみ書込)。下流はすべて案件IDで参照するため、
   取込で列ズレ・行ズレが下流に波及しない

**取り込む項目**(実CSV確認済み:全60列・cp932/Shift-JIS。マッピング表は `設定_取込` に持ち、コード修正なしで変更可能):

| kintoneヘッダー名 | 用途 | 必須 |
|------------------|------|------|
| `案件ID` | 主キー(upsert) | ◎ |
| `案件名` | 表示 | ◎ |
| `取引先名` | クライアント名として表示 | ◎ |
| `納品予定日_終` | **請求月の自動導出元** | ◎ |
| `フェーズ` | 商談化/見積・提案中/受注/納品/完了/失注。**失注は分配対象外**として選択肢から除外 | ◎ |
| `案件所有者` | メール。メンバーマスタと照合し**メイン担当の初期値**。複数記載(改行区切り)は1行目を採用+警告。照合不可は空欄+警告 | ○ |
| `納品予定日_始` / `日数` | 参考表示 | ○ |
| `親案件ID` / `親案件名` | まとめ分配・グルーピングに使用 | ○ |

上記以外の約50列(金額系・住所系・帳票フラグ等)は取り込まない。

**kintoneの金額列を使わない理由(実データ検証済み)**:完了案件810件のうち約450件で
`利益_税抜 ≠ 売上 − 原価` となっており、評価に使える精度がない。売上/原価/粗利は本ツール側で
メイン担当が見積時・確定時の2回入力する。

**CSV取込の運用手順(文字化け対策込み・確定版)**【v2】:
GoogleドライブにCSVをアップロード → 右クリック → アプリで開く → Googleスプレッドシート
(Shift-JISが自動変換される)→ 全選択コピー → `kintone貼付` へ貼り付け。
この手順を運用ドキュメントの標準ルートにする。

### 5.2 入力フロー(すべてGASのカスタムメニュー/サイドバーフォーム経由)

| タイミング | 誰が | 何を |
|-----------|------|------|
| キックオフ時 | メイン担当 | 案件登録:案件IDを選択 → 見積時の売上/原価/粗利を入力(粗利=売上−原価を自動計算、手修正可) |
| メンバー招集時 | メイン担当 | 制作分配:メンバーと%を設定。残り%は自動でメイン担当に付く |
| 現場に入ったら | **本人** | 現場分配:案件・ポジション・日数(0.5刻み)・**稼働メモ(任意)**【v2】 |
| 案件終了時 | メイン担当 | 確定値入力:確定売上/原価/粗利(見積時の値は上書きされない) |

**フォーム共通仕様**【v2】:
- 案件選択は入力フィルタつき(datalist方式:IDか名前の部分一致で絞り込み)
- フォーム上部に「**選択できる案件: n件(除外条件の説明)**」を表示する
  (試用で「kintoneにあるはずの案件が出ない」という混乱が起きたため。
  除外条件=失注/登録済み/未登録/運用開始月より前、をフォームごとに明示)
- 数値はクライアント側でも即時計算・表示(現場分配の金額、制作分配の残り%)
- 送信結果はフォーム内に成功/エラーメッセージで表示

**個別仕様**:
- **現場分配**:単価と等級は入力時点の値をスナップショットして**値で固定保存**。
  案件登録前の案件にも入力可(固定額のため原資に依存しない)。
  **稼働メモ**【v2】:同一案件に複数回入る場合の区別用フリーテキスト(例「6/14-15 設営」)。
  入力は1回分まとめて日数指定でよい(稼働ごとに行を分けることは強制しない)
- **制作分配**:案件選択時に**設定済みの分配(メンバーと%)を表示**【v2】し二重登録に気づけるようにする。
  同一メンバーへの重複登録はエラー(変更は取消→再入力)。
  メイン担当自身の%指定はエラー(自動行が担うため)
- **確定値入力**:候補は「見積入力済み・確定未入力」のみ。入力時に見積値を参考表示。
  送信前に「再編集できない」旨の確認ダイアログ

### 5.3 まとめ分配(複数案件への一括適用)

シナハロのように1プロジェクトが多数の案件に分かれるケースのための**入力ショートカット**。データ構造は変えない。

1. 対象案件の選び方は2通り:**親案件を指定**(子案件+親自身が自動チェック、外すのも可)/**任意の案件を複数チェック**
2. 制作メンバーと%の組を1回だけ入力
3. GASが**選択した案件ごとに通常の制作分配行を生成**(同じ%を各案件に適用、同一の「まとめ分配ID」を付与)

- 分配額は案件ごとに「その案件の制作原資×%」で計算され、**その案件の請求月に計上**
- メイン担当の残り%自動計算も案件ごとに通常通り適用
- 生成後は普通の分配行なので、特定の子案件だけ後から個別調整可能(取消→再入力)
- 後から子案件が増えた場合は、新しい案件にだけ再度まとめ分配を実行
- 【v2】**1案件でもバリデーションNGなら全体を中断**(部分適用しない)。NG案件と理由を列挙表示
- **現場分配はまとめ分配の対象外**。代表案件を1つ指定して通常入力する

### 5.4 ビューでの親案件グルーピング
- 個人ビューの案件一覧は同一親案件の案件を連続表示+親案件単位の小計行
- グループ間・グループ内とも請求月の新しい順

## 6. シート詳細(列定義)

> 【v2原則】列の追加は**必ず末尾**に行う(既存データとの互換維持)。
> 列定義はコード内で一元管理し、読み書きはヘッダー名→位置の解決を介して行う(§10)。

### 6.1 `案件データ`(取込先)
案件ID / 案件名 / 取引先名 / フェーズ / 納品予定日_始 / 納品予定日_終 / 日数 /
請求月_自動 / 案件所有者メール / 所有者メンバー名 / 所有者警告 / 親案件ID / 親案件名 / 最終取込日時

### 6.2 `案件入力`(1行=1案件)
| 列 | 内容 | 入力/自動 |
|----|------|----------|
| 案件ID | 案件データから選択(失注・運用開始月前は選択肢に出さない) | フォーム |
| 案件名/クライアント/請求月_自動/親案件名 | 案件IDから自動参照(取込のたびに追従) | 自動 |
| 請求月上書き | 例外時のみ。空欄なら自動導出値 | フォーム |
| 適用請求月/半期 | 上書き優先で確定した請求月とその半期 | 自動 |
| メイン担当 | 初期値=kintone`案件所有者`の照合結果。変更可 | フォーム |
| 入力ステータス | 見積未入力/確定待ち(進行中)/確定済 を自動判定 | 自動 |
| 見積_売上/原価/粗利 | キックオフ時入力 | フォーム |
| 確定_売上/原価/粗利 | 終了時入力 | フォーム |
| ステータス | 進行中/確定済 | 自動 |
| 現場稼働合計 | 分配入力から自動集計 | 自動 |
| 制作原資_予測/確定 | 粗利−現場稼働合計 | 自動 |
| 制作%合計 | 自動行込みの合計(≠100なら警告) | 自動 |
| 警告 | 赤字/制作%不一致/等級条件違反/所有者警告/請求月未確定/存在しない案件ID | 自動 |
| 見積確定差額 | 確定粗利−見積粗利 | 自動 |
| 登録者/登録日時/確定入力者/確定入力日時 | GASが記録 | 自動 |

### 6.3 `分配入力`(1行=1人×1案件×1種別)
| 列 | 内容 |
|----|------|
| 分配ID | 一意ID(現場=F〜、制作=P〜、自動行=AUTO-案件ID) |
| 案件ID/案件名/請求月/半期 | 案件から自動(再計算で追従) |
| メンバー/種別(現場・制作) | 入力 |
| 【現場】ポジション/日数/稼働時等級/単価_1日/単価_半日/金額 | 入力時にマスタから取得し**値として固定保存** |
| 【制作】制作%/予測額/確定額 | 額は案件の制作原資×%で自動計算(原資が動けば追従) |
| 自動行 | TRUE=メイン担当の残り%行(GASが生成・更新。手動取消不可) |
| 無効 | TRUE=論理削除(取消) |
| 入力者/入力日時/まとめ分配ID/取消者/取消日時 | GASが記録 |
| 稼働メモ【v2】 | 現場稼働の区別用フリーテキスト(任意) |

- 制作%:メイン担当以外の合計が100%を超えたら**エラー(ハードブロック)**
- 現場分の予測額=確定額(固定単価)。制作分のみ予測/確定が乖離しうる

### 6.4 `集計`(非表示)
メンバー / 請求月 / 半期 / 確定額 / 予測額 / 見込額 / 関与案件数
(見込額 = 確定額があれば確定額、なければ予測額。ビューの「予測粗利(確定+進行中)」の元)

### 6.5 `監査ログ`(非表示)
日時 / 操作者 / 操作種別 / 案件ID / 対象 / 変更前 / 変更後 / 詳細(追記のみ・行削除しない)

## 7. ビュー仕様(フィルター操作なしで見たいものが見える)

共通方針:数字を出しすぎない。「半期サマリ」→「月別」→「明細」の段構成。

### 7.0 共通【v2】
- **半期は必ず期間つき表記**:`2026前期(2026/07〜2026/12)`
- 各ビューの2行目に**凡例+最終更新日時**を常時表示:
  「青帯=セクション見出し / グレー帯=列名 / 赤背景=警告・目標未達 / 金額=円(税抜)」
- 数字の定義(確定/見込/目標差額=見込−目標/達成率=確定÷目標)は利用ガイドに明記
- 更新手段は3つ:①メニュー「ビュー更新」 ②セレクタ(B1)変更時の自動更新(onEdit)
  ③**時間主導トリガーによる定期自動更新(約1時間ごと・管理者メニューでON/OFF)**【v2】
  ※ページリロードでは更新されないことをガイドに明記

### 7.1 `V_個人`
上部プルダウンで自分を選択(初期値はGASで開いた人のメールから自動セット)。上から:

1. **あなたのやること**:
   - 自分が案件所有者なのに未登録の案件(kintone取込済・失注以外)
   - 自分がメイン担当で「見積未入力」の案件
   - 自分がメイン担当で請求月を過ぎたのに「確定待ち」の案件
   - 自分の制作%が未設定(0%)の案件(メイン担当への催促材料)
   - ※運用開始月より前の案件は出さない【v2】
2. **今半期サマリ**:目標 / 確定粗利 / 予測粗利(確定+進行中) / 目標差額 / 達成率
3. **月別表**(請求月ベース、当半期6ヶ月+データのある先の月):確定 / 見込 / 関与案件数。
   先の月には計上先半期を注記
4. **今半期の案件別内訳**【v2】:どの案件でいくら粗利を出したかの積み上げ。
   見込額の大きい順に、案件名/役割/見込額/**構成比(自分の半期見込に占める%)**/確定額/ステータス。
   ※「分配入力シートを見渡さないと内訳が確認できない」という試用フィードバックへの対応
5. **次半期以降の計上分**:半期(期間つき)ごとの見込額(稼働したのに見えない、を防ぐ)
6. **自分の案件一覧(全期間)**:関わっている案件(メイン/現場/制作)を新しい順に。
   親案件グルーピング+小計行。警告のある行は赤背景

### 7.2 `V_ユニット`
- ユニット選択プルダウン
- **ユニットサマリ**:ユニット目標(=メンバー目標合計)/確定/見込/差額/達成率
- **メンバー横並び表**:各人の等級/目標/確定/見込/差額/達成率/関与案件数。
  **見込を足しても目標に届かないメンバーを赤背景でハイライト** → アサイン相談のトリガー
- ユニット長自身もプレイングマネージャーとして同じ表に載る
- **未入力・要対応一覧**:メンバー別のやること(ユニット長が声をかけられる)

### 7.3 `V_経営`
- 半期サマリ:全社+ユニット別の並列比較
- 月別推移:全社・ユニット別の確定/見込
- ユニット別のメンバー横並び表を縦に並べる(別ページに分散させない)

## 8. 権限・保護・改ざん防止

### 8.1 シート保護の現実解【v2重要】
コンテナバインドGASは「メニューを実行した本人」の権限で動くため、
**メンバーの操作が書き込むシートをハード保護にするとフォーム送信自体が失敗する**。
第1フェーズは以下で運用する:

- `設定_*`:管理者のみ編集可(**ハード保護**)
- `案件データ`/`案件入力`/`分配入力`/`集計`/`監査ログ`/各ビュー:**警告付き保護**
  (直接編集時に警告ダイアログ。完全には防げないことを許容し、監査ログ+再計算上書きで検知・修復)
- `kintone貼付`:保護なし
- ビューはセレクタセル(B1)のみ警告なしで編集可
- 完全なハード保護が必要になったら、第2フェーズでWebアプリ(オーナー権限実行)化を検討

### 8.2 改ざん防止(評価に直結するため)
- 確定値は一度入力したら**フォームからも再編集不可**。修正は管理者の「確定値修正」のみ
- 現場分配のスナップショット値(等級/単価/金額)は入力後変更不可。取消→再入力で対応
- **削除はしない**:分配の取消は「無効」フラグの論理削除。自動行は取消不可
- **監査ログ**:全フォーム操作・管理者操作について 日時/操作者/操作種別/案件ID/変更前→変更後 を追記
- **半期締め**(管理者メニュー):締めた半期の案件・分配はフォーム経由の全操作を拒否

### 8.3 管理者メニュー
初期セットアップ / 保護を再設定 / 確定値修正 / 請求月上書き修正 / 半期締め /
ビュー自動更新の有効化・無効化【v2】

## 9. 「壊れない」ための設計原則【v2で大幅強化】

第1次実装で「ユーザーが普通にシートを触っているうちに徐々に壊れる」事象が発生した。
v2では以下を**必須要件**とする:

1. **設定シートの横並びブロック禁止**:v1は1シートに複数の表を列位置固定で並べたが、
   行・列の挿入/削除/並べ替えで読み取り位置がズレて静かに壊れた。
   v2は「1シート=1つの縦持ち表(1行目ヘッダー)」に分割する(§3)
2. **読み書きとも、ヘッダー名→列位置の動的解決を介する**:自前シートでも列位置を信用しない。
   各操作の冒頭でヘッダー行を読み、期待するヘッダー名と照合する。
   **不一致(列の削除・改名を検知)なら操作を中断して「どの列が壊れたか+初期セットアップで修復できる」旨を明示**。
   黙って間違った列に書かない
3. **列追加は末尾のみ/列の改名・削除はマイグレーションとして扱う**:
   設定_一般に「スキーマバージョン」を記録し、初期セットアップは
   旧バージョンからの差分(列追加・設定キー追加・書式適用)を冪等に適用する。
   **初期セットアップは何度実行してもデータを消さない**(これはv1から維持)
4. **請求月・日付列はプレーンテキスト書式(@)**:`2026/07` のような文字列を書き込むと
   Sheetsが日付値へ自動変換し、文字列比較・google.script.run の返却(Date不可)が壊れる。
   セットアップで対象列に `@` 書式を設定し、読み出し側も Date/文字列両対応の正規化関数を通す
5. **金額列は `#,##0` 書式**:値は数値のまま、表示だけカンマ区切り【v2】
6. **入力はGASフォーム経由を基本**とし、数式は人の触る行に置かない。集計はGASが書き出す
7. **バリデーション**:案件ID・メンバー・ポジションはすべてマスタ参照の選択式。フリーテキスト最小化
8. **警告は止めない**:赤字・%不一致・等級条件違反は警告表示
   (ハードブロックは ①他メンバー%合計>100 ②マスタ不整合 ③締め済み半期 ④確定値の再入力 のみ)
9. **ビュー描画は毎回フルクリア→フル再描画**(差分更新しない)。描画開始行より上(セレクタ・凡例)は触らない

### 台帳としての「誰が入力すべきか」の見える化
- `案件入力` シート自体が台帳:メイン担当・入力ステータスが全行に明示される
- `V_個人` の「あなたのやること」枠と `V_ユニット` のメンバー別未入力一覧(§7)

## 10. 実装スタック・GAS実装上の注意(第1次実装で確認済みのハマりどころ)

- スタック:Google Sheets + GAS(**clasp管理**)。外部サービスなし。V8ランタイム、タイムゾーン Asia/Tokyo
- リポジトリ構成:`src/` にGASソース(番号プレフィックスで役割分け)+HTMLフォーム、
  `test/` にモックテスト、`docs/` に運用ドキュメント。`.clasp.json` はgit管理外(`.clasp.json.example` を置く)
- oauthScopes:`spreadsheets.currentonly` / `userinfo.email` / `script.container.ui` /
  `script.scriptapp`(時間主導トリガー用)【v2】。**スコープ追加時はユーザーに再承認が発生する**ことを周知
- `onOpen` でカスタムメニュー生成。`Session.getActiveUser().getEmail()` でメンバーマスタと照合し、
  個人ビュー初期選択と入力者記録に使用
- パフォーマンス:30名×年間数百案件規模。getValues/setValuesの一括処理で十分。全件再計算方式でよい
- **google.script.run はDateオブジェクトを返せない**:フォームへ渡す値は文字列/数値に正規化する
- **setValueで'2026/07'等を書くと日付に自動変換される**:§9-4のテキスト書式で防ぐ
- simple trigger(onEdit/onOpen)は権限が限定される:ビュー更新程度に留め、失敗時はトーストで通知
- 時間主導トリガーは「設定した人」の権限で実行される(管理者が設定する)
- HTMLフォームは datalist で検索可能なセレクタを実装(数百〜千件で実用十分)。
  候補件数の明示を必須とする(§5.2)
- **clasp は 2.4.2 にバージョン固定**(3系はコマンド体系が異なるためマニュアルと不一致になる)。
  `clasp create --type sheets --title "…" --rootDir src`。
  既知のつまずき:Apps Script API未有効/ZIP展開の二重フォルダ(srcが見えない場所での
  create は `ENOENT: src/.clasp.json` で部分失敗する。復旧は .clasp.json の手動作成)

```
見積:売上1,000,000 / 原価200,000 → 見積粗利800,000

取消:Bさん行を取消 → 無効フラグ、自動行が100%に復帰
赤字:粗利300,000にスタッフ16日(400,000) → 原資 -100,000 のまま按分+赤字警告
```
